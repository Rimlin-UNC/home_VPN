# Разбор ТЗ v2: что не учтено и какие решения приняты

Документ отвечает на вопрос заказчика «возможно, что-то не учёл». Каждый пункт: **проблема** →
**решение в StealthNode 2.0.0** → где проверяется. Состояние на 14.10.2026: Xray-core v26.10.10,
3X-UI v3.10.0, Hysteria v2.13.0, Caddy 2.11.

Сводка по важности: 🔴 — без исправления не работает или небезопасно, 🟠 — заметный риск,
🟡 — улучшение.

## 1. Архитектура и порты

| # | Проблема в ТЗ | Решение | Проверка |
|---|---|---|---|
| 1.1 🔴 | Caddy по ТЗ отдаёт панель по HTTPS на 443, но 443/tcp занят Xray (XHTTP + REALITY). Два процесса не могут слушать один порт. | Caddy работает на **отдельном порту** (случайный 20000–29999), 443 остаётся за Xray. | `doctor`: порты |
| 1.2 🔴 | При занятом 443 Let's Encrypt не может проверить домен через TLS-ALPN-01. | Только HTTP-01 на :80 (`disable_tlsalpn_challenge`), 80/tcp открыт в UFW. Редирект с :80 отключён, чтобы не раскрывать порт панели. | CI, `doctor`: HTTPS панели |
| 1.3 🔴 | Ссылка подписки на 443 невозможна по той же причине. | Подписка: `https://ДОМЕН:ПОРТ_ПАНЕЛИ/СЛУЧАЙНЫЙ_ПУТЬ/<subId>` через тот же Caddy. | `doctor`: подписка |
| 1.4 🔴 | В UFW предлагалось открыть «порт панели» — у 3x-ui это сырой HTTP-порт (2053) без TLS; подписка 2096 тоже. | Панель и сервер подписки слушают **только 127.0.0.1**; наружу — только Caddy с TLS. В UFW: SSH, 80, 443/tcp, 8443/tcp, 443/udp, порт Caddy. | `doctor`: «только локально» |
| 1.5 🟠 | Отдельная служба `xray.service` (шаг 2 ТЗ) конфликтует с 3x-ui: панель сама запускает и перезапускает своё ядро Xray. | Отдельный Xray не ставится. `/opt/stealthnode/xray/config.json` — экспорт работающего конфига для справки (`stealthnode export-config`). | `doctor`: x-ui, процесс Xray |
| 1.6 🟠 | Hysteria2 отдельным бинарником с одним общим паролем: обходит лимиты трафика и IP (требование ТЗ), не попадает в подписку, лишняя служба. | Hysteria2 — **инбаунд Xray под управлением 3x-ui**: у каждого пользователя свой `auth`, общая квота с VLESS, профиль в той же подписке. Файлы `/opt/stealthnode/hysteria/server.{crt,key}` сохранены (путь из ТЗ). | `contract_check`, E2E |
| 1.7 🟡 | Caddy по умолчанию включает HTTP/3 (UDP 443), который занят Hysteria2. | HTTP/3 у Caddy выключен (`protocols h1 h2`). | `caddy validate` |

## 2. Протоколы и маскировка

| # | Проблема | Решение | Проверка |
|---|---|---|---|
| 2.1 🔴 | Hysteria2 с `insecure=1` и self-signed `CN=max.ru`: любой посредник может подменить сертификат (MITM). Кроме того, **Xray-core ≥ 26 удалил `allowInsecure`** — такие ссылки в Xray-клиентах (v2rayNG, v2rayN, Happ) не работают. | Сертификат **Let's Encrypt**, который Caddy уже получил для домена (синхронизация таймером). До его получения — долгоживущий self-signed + `pinSHA256` (отпечаток в ссылке, MITM невозможен). | E2E: `test_ca_mode_*`, `test_profile_works…[hysteria2]` |
| 2.2 🟡 | Официальный клиент Hysteria2 считает `pinSHA256` *дополнительной* проверкой и всё равно требует доверенный CA. | Основной режим — Let's Encrypt (подходит всем клиентам). Временный self-signed режим рассчитан на Xray-клиенты; для официального клиента нужен `insecure=1`+pin (описано в CLIENTS.md). | E2E: `test_hysteria2_official_client_pin_needs_insecure` |
| 2.3 🟡 | `masquerade` для Hysteria2 при Salamander бесполезен: без пароля obfs QUIC-рукопожатие вообще не начинается, маскировку никто не увидит. | Не настраивается. | — |
| 2.4 🔴 | **Xray ≥ 26.9.8: REALITY отвергает ClientHello без X25519MLKEM768.** Клиенты на ядре sing-box (NekoBox, Nekoray/Throne, Hiddify, Karing, sing-box), Mihomo с отпечатком ≠ chrome и отпечатки `ios/edge/360/qq` не подключаются. ТЗ этого не учитывает (и рекомендации многих гайдов 2025 года устарели). | Список совместимых клиентов в [CLIENTS.md](CLIENTS.md): v2rayNG, v2rayN, Happ, Streisand/V2Box (iOS) на Xray-core ≥ 26.3.23. | E2E: `test_reality_rejects_fingerprint_without_mlkem` |
| 2.5 🟢 | `fp=firefox` в ТЗ — **верно** и, более того, единственно возможно: с июня 2026 ТСПУ замораживает TLS-сессии с отпечатками Chrome/Safari/iOS при > 3 параллельных сессиях к одному SNI, а без MLKEM (Edge/360/QQ/iOS) не пускает сам REALITY. Firefox (≥ 148 в uTLS) проходит оба ограничения. | `fp=firefox` во всех ссылках, `doctor` проверяет ссылки. | `links.audit`, `contract_check` |
| 2.6 🟢 | `mode=stream-one` явно — **верно**: `auto` в связке с REALITY ломается у части клиентов (Xray #5635, v2rayN #8738). | Явно на сервере и в ссылках. | `contract_check` |
| 2.7 🟠 | 3x-ui 3.x подставляла в XHTTP `scMaxEachPostBytes`/`scMinPostsIntervalMs=30` — с июня 2026 это детектируется ТСПУ. | Эти поля не задаются; `provision` исправляет их при дрейфе, `doctor` проверяет `extra` в ссылках. | unit: `test_provision_repairs_drift` |
| 2.8 🟠 | SNI `max.ru`/`yandex.ru` на **зарубежном** сервере: российский сервис на европейском IP — несоответствие, заметное DPI; цель REALITY должна быть доступна с VPS и поддерживать TLS 1.3 + h2 + X25519. Гайд, на который ссылается ТЗ, рекомендует для зарубежного сервера зарубежный SNI из той же сети, а `max.ru` — для российского relay. | По умолчанию — как в ТЗ (`max.ru`), но параметр `--sni` и команды `stealthnode sni-check` (проверка кандидатов с самого сервера: TLS 1.3, h2, группа, задержка) и `stealthnode sni-set`. | `doctor`: цель REALITY |
| 2.9 🟠 | Режим «белых списков» мобильных операторов (2025–2026): при его включении зарубежные IP недоступны совсем, никакая маскировка не поможет. | Вне рамок одного сервера. План фазы 2 — российский relay-VPS (VLESS+TCP+REALITY → зарубежный XHTTP), см. [PLAN.md](../PLAN.md). | — |
| 2.10 🟡 | Xray 26 по умолчанию не пускает клиентов VLESS/Hysteria2 в приватные сети сервера. | Оставлено (защита локальной сети VPS). | E2E |

## 3. Домен и сертификаты

| # | Проблема | Решение |
|---|---|---|
| 3.1 🟠 | Домен в зоне **.ru** (реестр под юрисдикцией РФ: возможна блокировка/разделегирование) и слово **«vpn»** в имени. Любой сертификат Let's Encrypt попадает в публичные CT-логи (crt.sh), где сканеры ищут именно «vpn». | По решению заказчика оставлен `vpn.shprv.ru`, но это **параметр** `--domain`. Риск описан; установщик предупреждает. Для смены достаточно новой A-записи и `install.sh --domain новый.домен` (ссылки обновятся через подписку). |
| 3.2 🟡 | TTL A-записи не оговорён. | Рекомендуется TTL 300: при блокировке IP переезд на новый VPS (`--restore`) без смены ссылок. |

## 4. Безопасность сервера

| # | Проблема | Решение |
|---|---|---|
| 4.1 🔴 | На Ubuntu 24.04 sshd пишет журнал только в journald, а fail2ban по умолчанию читает `/var/log/auth.log` — jail sshd не работает. | `backend = systemd` для sshd; jail проверяется после запуска. |
| 4.2 🔴 | В Ubuntu 24.04 SSH запускается через `ssh.socket`: порт задаёт сокет-юнит, генератор Ubuntu выставляет `BindIPv6Only=ipv6-only`, и наивный drop-in `ListenStream=ПОРТ` оставляет SSH **только на IPv6** (поймано нашим CI) — на IPv4-сервере это потеря доступа. | Порты задаются строками `Port` и применяются штатным `sshd-socket-generator`; каждый порт проверяется реальным IPv4-подключением, при неудаче — явные сокеты IPv4/IPv6, а если и это не помогло — **автоматический откат**. Новый порт добавляется к 22, а 22 закрывается отдельным шагом `--ssh-close-22`. «Только ключи» — лишь если ключ уже есть в `authorized_keys`. |
| 4.3 🟠 | «Защита панели от перебора» не конкретизирована. | Встроенный лимит 3x-ui (5 ошибок/5 мин → 15 мин) + jail `stealthnode-panel` (5 ошибок/10 мин → 24 ч) по журналу панели с реальным IP (через Caddy) + `recidive` (3 бана/сутки → неделя). Фильтр устойчив к подстановке IP через логин. |
| 4.4 🟠 | Пакет `nftables` (его ставит 3x-ui ради fail2ban) содержит службу, которая при загрузке делает `flush ruleset` и стирает правила UFW. | Служба `nftables` не включается; баны fail2ban — через iptables-nft, совместимо с UFW. |
| 4.5 🟡 | Автообновления упомянуты, но не настроены. | Только security-обновления Ubuntu; перезагрузка при обновлении ядра в 01:30 UTC (04:30 МСК), отключается `--no-auto-reboot`. |
| 4.6 🟡 | Резервные копии не предусмотрены. | Ежедневно (хранится 14): БД панели (онлайн-снимок SQLite), `.env`, профили, сертификаты; `--restore` для переезда. |
| 4.7 🟡 | Секреты: в ТЗ перечислены файлы, но не права каталогов. | `/opt/stealthnode` и подкаталоги 700, файлы с секретами 600; `doctor` проверяет. |

## 5. Пользователи и лимиты

| # | Проблема | Решение |
|---|---|---|
| 5.1 🔴 | В старых версиях 3x-ui лимит трафика задаётся **на инбаунд**: три профиля = три отдельные квоты по 50 ГБ, и один человек мог бы израсходовать 150 ГБ. | В 3x-ui v3 клиент — одна запись, привязанная ко всем инбаундам: **одна квота на человека**. Ежемесячный сброс — `trafficReset=monthly`; после сброса пользователь включается автоматически. |
| 5.2 🟠 | Лимит IP = 1 на мобильном интернете (CGNAT, переключение Wi-Fi ↔ LTE) даёт ложные блокировки. | По умолчанию 2 IP для родственников, без лимита — для владельца. |
| 5.3 🟡 | «Одна подписка для всех профилей» — в 3x-ui v3 так и есть (общий `subId`), но адрес в ссылках по умолчанию берётся из заголовка Host запроса. | Адрес ссылок жёстко = домен (`shareAddrStrategy=custom`). |
