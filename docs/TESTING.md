## 2. Ручные проверки при приёмке

### С телефона (мобильный интернет в РФ)
1. Импортируйте подписку ([CLIENTS.md](CLIENTS.md)), подключитесь к **SN-XHTTP**.
2. Откройте `https://2ip.ru` — должен быть IP сервера.
3. Скорость: `https://speedtest.net` (или приложение) — критерий ТЗ ≥ 20 Мбит/с.
4. Повторите для **SN-TCP-iOS** (на iPhone) и **SN-HY2**.

### Лимит трафика
```bash
stealthnode user add limittest --gb 0.05 --ip 1      # 50 МБ
stealthnode user show limittest --qr                 # подключите телефон
# скачайте файл > 50 МБ через VPN; через 10–30 с соединение оборвётся
stealthnode user list                                # limittest: ВЫКЛ
stealthnode user del limittest --yes
```

### Лимит IP
Подключите `limittest` (`--ip 1`) с двух сетей одновременно (Wi-Fi и мобильная) — один из
адресов будет заблокирован на 30 минут (`fail2ban-client status 3x-ipl`).

### fail2ban SSH
С другого IP трижды введите неверный пароль/ключ (`ssh wrong@<IP>`), затем
`stealthnode unban` — IP в списке `sshd`; разбан: `stealthnode unban <IP>`.

### Перебор пароля панели и восстановление доступа
1. Пять неверных паролей подряд — шестой вход **с верным** паролем тоже отвергается
   (лимит 3x-ui, 15 минут); с другой сети (мобильный интернет) вход работает.
2. Ещё пять неверных паролей под другим логином (всего 10 за час) — панель с этого IP перестаёт
   открываться; `stealthnode unban` показывает IP в `stealthnode-panel`.
3. `sudo stealthnode panel-password` — новый пароль подходит сразу, бан снят.
4. Смените пароль в веб-интерфейсе и запустите `install.sh` повторно — пароль сохраняется,
   `stealthnode panel-password --check` пишет «изменены в веб-интерфейсе».

Всё это автоматически проверяет CI (шаги «Пароль панели…» и «Блокировка входа…»).

## 3. Автотесты (репозиторий)

| Набор | Что проверяет | Запуск |
|---|---|---|
| `tests/unit` (pytest, 55+) | пароль панели: bcrypt 3x-ui через libcrypt (вектор Go x/crypto), состояния match/changed/default/missing, смена через `x-ui setting` с проверкой по БД, снятие банов только для панели, запрет `env set` для пароля; X25519 по векторам RFC 7748; формат `.env` (совместимость с bash); генерация параметров и идемпотентность; JSON инбаундов (stream-one, firefox, без sc*-полей, salamander, pin); клиенты (байты, ежемесячный сброс); разбор и аудит ссылок; провижининг, исправление дрейфа, конфликты портов, пользователи, cert-sync, бэкап/восстановление (в т.ч. защита от path traversal) — против фейкового API 3x-ui | `python -m pytest tests/unit` |
| `tests/bats` | функции установщика: шаблоны (буквальная подстановка), повторы, валидация параметров, `--help`; повторный запуск не трогает пароль панели, изменённый в веб-интерфейсе | `bats tests/bats` |
| `tests/e2e` | **настоящий Xray 26.10.10** (сервер и клиент) + официальный клиент **Hysteria 2.13**: все три профиля; self-signed+pin и CA-режим; отказ при `fp=ios` (нет MLKEM), неверном пароле obfs и shortId | `pip install xray-core==1.8.26.13 hysteria2==2.13.0` (Python 3.11), `python -m pytest tests/e2e` |
| CI `e2e-install` | **полная установка на чистой Ubuntu 24.04** (GitHub Actions), `doctor --e2e --speed`, проверка контракта с настоящей 3x-ui (`tests/ci/contract_check.py`), фильтр fail2ban (`fail2ban-regex`, отказы лимита 3x-ui не считаются), управление пользователями, **смена пароля через веб-интерфейс → повторная установка → пароль сохранён** (вход как в браузере: HTTPS через Caddy, CSRF, cookie), **лимит 3x-ui и бан fail2ban с отдельного IP → восстановление `stealthnode panel-password`**, `--admin-ip` запоминается, бэкап и восстановление, усиление SSH (порт 2222, только ключи, закрытие 22) | автоматически при push |
| Линтеры | shellcheck (style), shfmt, ruff, `caddy validate` (в установщике) | CI, `make lint` |

В CI используется `--tls internal` (у раннера нет домена) — выпуск Let's Encrypt проверяется
только на реальном сервере (`doctor`: «сертификат панели»).
