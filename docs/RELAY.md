# Связка: российский мост → зарубежный выход

Когда из России зарубежный сервер недоступен, клиенты подключаются к серверу **в РФ (мост)**,
а он передаёт их трафик на **зарубежный сервер (выход)**. Для родственников ничего не меняется:
ссылки, QR-коды и подписки те же.

## Зачем это нужно

С 2026 года ТСПУ «замораживает» прямые подключения пользователей из РФ к зарубежным хостингам:
после 15–20 КБ данных в одной TCP-сессии пакеты перестают доходить, а IP многих хостингов
недоступны целиком. Трафик внутри страны и обмен «сервер–сервер» фильтруются гораздо мягче.
Поэтому сейчас рабочая схема — цепочка через российский сервер
([Хабр, февраль 2026](https://habr.com/ru/articles/985674/),
[Хабр, апрель 2026](https://habr.com/ru/articles/1021160/)).

Ваш случай: выход — **95.182.99.147** (Рига, HostVDS), мост — **31.59.126.178** (Москва, RocketCloud).

## Как устроено

```
 Клиент в РФ ──VLESS+REALITY──▶  МОСТ 31.59.126.178 (Москва)  ──VLESS+XHTTP+REALITY──▶  ВЫХОД 95.182.99.147 (Рига) ──▶ интернет
 (те же ссылки,                   панель 3X-UI, пользователи,      один поток «сервер–сервер»,
  домен vpn.shprv.ru)             лимиты, подписки                 порт открыт только для моста
                                        │
                                        └──▶ российские сайты напрямую (банки и госуслуги видят российский IP)
```

- **Мост** — полноценный StealthNode: панель, пользователи с лимитами, подписки, Hysteria2.
  Всё переносится с выхода архивом (`--restore`): тот же домен, ключи REALITY, пользователи
  и подписки, поэтому клиентам ничего настраивать не нужно. Панель открывается по прежнему адресу
  с прежним логином. Telegram-бот работает через выход (в РФ Telegram заблокирован).
- **Выход** получает отдельный инбаунд для моста (VLESS + XHTTP stream-one + REALITY) на случайном
  порту 40000–49999. UFW открывает этот порт **только для IP моста**, поэтому сканеры и ТСПУ его
  не видят. Мост входит под отдельной учётной записью `sn-bridge` без лимитов и никогда не банится
  fail2ban.
- **Российские сайты** (.ru, .su, .рф, ВК, Яндекс, Сбер и российские IP) мост отправляет напрямую.
  Так работают банки и госуслуги, а зарубежный канал не тратится. Отключается флагом
  `--no-ru-direct`.
- **Лимиты.** Квоты и лимит IP считает мост: он видит настоящие IP клиентов.

## Что понадобится

- Российский сервер: Ubuntu 24.04, от 1 ГБ RAM, свободные порты 80, 443/tcp, 443/udp и 8443, вход root по SSH.
- Доступ к DNS домена `shprv.ru`.
- Около 20 минут.

## Шаг 0. Видит ли мост выход

Если звено «мост → выход» тоже режется, связка не поможет. Проверьте с **российского** сервера:

```bash
timeout 5 bash -c '</dev/tcp/95.182.99.147/443' && echo "TCP до выхода: OK"
curl -sv --connect-timeout 5 --resolve max.ru:443:95.182.99.147 https://max.ru/ -o /dev/null 2>&1 | grep -m1 'subject:'
```

Во второй строке должен быть сертификат `max.ru`: так REALITY на выходе отвечает без ключа.
Тайм-аут означает, что IP выхода недоступен даже из российского дата-центра. Тогда смените IP
у хостера (или возьмите другой VPS) и повторите.

## Шаг 1. Выход — зарубежный сервер 95.182.99.147

```bash
cd home_VPN && git pull
sudo bash stealthnode/install.sh           # обновить StealthNode (повторный запуск безопасен)
sudo stealthnode exit enable 31.59.126.178
```

Команда создаст инбаунд и учётную запись моста, откроет порт только для моста и сделает свежий
архив. В конце она напечатает **ссылку выхода** (`vless://…`, это секрет) и готовую команду для
моста. Показать ссылку снова: `sudo stealthnode exit link`.

## Шаг 2. DNS

A-запись `vpn.shprv.ru` → **31.59.126.178** (TTL 300). Если есть AAAA-запись, удалите её.
Проверка: `dig +short vpn.shprv.ru` должна вернуть `31.59.126.178`.

Менять DNS лучше до шага 4: тогда мост сразу получит сертификат Let's Encrypt.

## Шаг 3. Архив — на мост

С российского сервера (или через ваш компьютер):

```bash
scp root@95.182.99.147:/opt/stealthnode/backups/stealthnode-ДАТА.tar.gz /root/
```

## Шаг 4. Мост — российский сервер 31.59.126.178

```bash
git clone -b arena/f556f089-home-vpn https://github.com/Rimlin-UNC/home_VPN.git && cd home_VPN
sudo bash stealthnode/install.sh --domain vpn.shprv.ru \
  --restore /root/stealthnode-ДАТА.tar.gz \
  --exit-link 'vless://…ссылка из шага 1…'
```

**Если с российского сервера не открывается GitHub,** скопируйте репозиторий с выхода
(`scp -r root@95.182.99.147:~/home_VPN /root/`) и пустите загрузки через SSH-туннель к выходу:

```bash
ssh -fN -D 1080 root@95.182.99.147
sudo bash stealthnode/install.sh --domain vpn.shprv.ru --restore /root/stealthnode-ДАТА.tar.gz \
  --exit-link 'vless://…' --proxy socks5h://127.0.0.1:1080
```

Через прокси идут только загрузки по HTTPS (3x-ui с GitHub, Caddy). Внешний IP моста
определяется напрямую.

## Шаг 5. Проверка

На мосту: `sudo stealthnode doctor --e2e`. В разделе «Связка» должно быть:

```
[ OK ] мост: выход 95.182.99.147:4xxxx доступен — TCP … мс, TLSv1.3, маскировка CN=*.max.ru
[ OK ] мост: трафик по умолчанию идёт на выход
[ OK ] мост: трафик выходит в интернет через выход — внешний IP 95.182.99.147 — зарубежный выход
[ OK ] мост: российские сайты — напрямую — их видят с IP моста 31.59.126.178
```

С телефона в России: обновите подписку в приложении и подключитесь. Свой IP смотрите на
**ifconfig.me**: там должен быть 95.182.99.147. **2ip.ru** покажет 31.59.126.178, потому что
российские сайты идут напрямую с моста. Это нормально.

## Что меняется

| Кто | Что |
|---|---|
| Родственники | Ничего. Если приложение не обновило подписку само, нажмите «Обновить». |
| Владелец | Панель — по прежнему адресу (теперь её обслуживает мост). Пользователей заводите **на мосту**. Ежедневные архивы делает мост — копируйте их к себе. |
| Выход | Работает как раньше, плюс инбаунд для моста. Пользователи в его панели остались от старой схемы. Новых туда не добавляйте. |

Из Финляндии ссылки по домену тоже идут через Москву (Хельсинки → Москва → Рига). Работает,
но с чуть большей задержкой.

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `doctor`: «мост: выход … недоступен» | IP выхода режется из российского ДЦ или нет правила UFW на выходе | На выходе: `sudo stealthnode exit status`. Повторите шаг 0. При блокировке смените IP выхода (ниже). |
| Подключение есть, но сайты не открываются | Выход недоступен или выключен | На мосту: `sudo stealthnode bridge status`. |
| С мобильного интернета не работает ничего, с домашнего — работает | Оператор включил «белые списки», а IP моста в них не входит | Без VPN откройте на телефоне `https://vpn.shprv.ru:<порт панели>/`. Если страница не грузится, IP не в белом списке. Нужен мост в облаке, чьи адреса в списках (например, Yandex Cloud). |
| Нужно сменить выход (новый зарубежный VPS) | — | На новом выходе: `sudo stealthnode exit enable 31.59.126.178`. На мосту: `sudo stealthnode bridge set 'новая ссылка'`. Пользователям ничего делать не нужно. |
| Нужно временно выключить связку | Диагностика | На мосту: `sudo stealthnode bridge off`. Трафик пойдёт с самого моста (заблокированные в РФ сайты открываться не будут). Включить снова: `sudo stealthnode bridge set 'ссылка'`. |

## Команды

| Где | Команда | Что делает |
|---|---|---|
| выход | `stealthnode exit enable <IP моста> [--port N]` | включить режим выхода; напечатать ссылку и инструкцию |
| выход | `stealthnode exit link` | ссылка выхода для моста |
| выход | `stealthnode exit status` | инбаунд, правило UFW, трафик моста |
| выход | `stealthnode exit disable` | выключить (инбаунд, учётная запись, правило UFW удаляются) |
| мост | `install.sh … --exit-link 'vless://…' [--no-ru-direct]` | установка моста (с `--restore <архив выхода>`) |
| мост | `stealthnode bridge set 'vless://…' [--no-ru-direct]` | включить или сменить выход (сначала проверяет, что выход доступен) |
| мост | `stealthnode bridge status` / `off` | проверить выход / выключить связку |

## Безопасность и приватность

- Мост находится в РФ и снимает внешний слой VLESS, как любой вход цепочки. HTTPS сайтов
  остаётся зашифрованным от устройства до сайта. Мосту видны имена сайтов (SNI) и объём трафика.
- Домены зарубежных сайтов мост не разрешает (маршрутизация `AsIs`): DNS-запросы к ним делает
  выход, поэтому в российский DNS они не утекают.
- Выход не виден снаружи: порт для моста открыт только для IP моста. Пользовательские порты
  выхода по-прежнему работают (на случай прямого подключения из-за рубежа).
- Если мост изъят или взломан, смените ключи: `stealthnode exit disable` на выходе и переустановка
  моста с новыми ключами REALITY (пользователям — новые подписки).

## Как это проверено

- **Локальный E2E на настоящем Xray 26.10.10** (`tests/e2e/test_chain.py`): клиент → мост →
  выход. Все три профиля (XHTTP, Vision, Hysteria2) выходят в интернет с выхода. Сайты `.ru`
  идут с моста. Без выхода зарубежные сайты недоступны, российские работают.
- **CI на настоящей 3X-UI** (Ubuntu 24.04): обе роли на одном сервере через петлю 127.0.0.1.
  Шаблон (исходящий на выход, `geoip:ru`, правило против петли) принят панелью и Xray,
  `doctor --e2e` проходит, счётчик трафика учётной записи моста растёт, выключение всё
  возвращает.
- **Не проверено** (нужны ваши серверы): реальные российские сети (мобильный интернет, белые
  списки) и реальное звено Москва → Рига. Шаг 0 и `doctor --e2e` на мосту проверяют именно это.
