# Техническое задание для ИИ-агента: Разработка персонального VPN-сервера «StealthNode» (Single-Server Edition)
## 0. Роль и режим работы агента
Ты — **Senior DevOps Engineer, Cybersecurity Architect и Fullstack Developer**. Твоя задача — спроектировать и написать код для автоматического развёртывания персонального VPN-сервера с веб-панелью администратора на **одном** VPS, работающего в условиях жёсткого DPI-фильтинга (Россия, 2026+). На этом же сервере параллельно будет работать торговый бот для биржи OKX.

**Формат результата:** готовый bash-скрипт `install.sh`, который скачивается на чистый сервер с Ubuntu 24.04 LTS, запускается одной командой и полностью настраивает систему. Все компоненты изолированы в Docker.

## 1. Инфраструктура: один сервер, бюджет до 600 ₽/мес
### 1.1. Требования к VPS
| Параметр | Значение |
|---|---|
| **Количество серверов** | **Один** VPS |
| **ОЗУ** | 2 ГБ (минимум 1 ГБ, рекомендуется 2 ГБ) |
| **CPU** | 1–2 vCPU |
| **Диск** | 20–50 ГБ SSD/NVMe |
| **Бюджет** | **До 600 ₽/мес** |
| **Оплата** | **Карта МИР** (обязательно) |
| **ОС** | Ubuntu 24.04 LTS |
| **Локация** | Россия или дружественная страна (Беларусь, Казахстан) |
**Почему один сервер, а не два:** пользователь имеет ограниченный бюджет. Двухсерверная схема (российский VPS → европейский VPS) не укладывается в 600 ₽/мес. Решение: один VPS с двумя публичными IP (основной + дополнительный) для разделения входящего и исходящего трафика, либо один VPS с policy routing через IPv6.
### 1.2. Сравнение хостингов с оплатой картой МИР
| Хостинг | Тариф | RAM | Диск | Цена/мес | Оплата МИР | Локация | Примечание |
|---|---|---|---|---|---|---|

### 1.3. Рекомендация ИИ-агенту
**Основной выбор: VDSina.ru Standard (600 ₽/мес, 2 ГБ RAM, 50 ГБ NVMe).**
- Точно укладывается в бюджет.
- VDSina.com (Нидерланды) позволяет арендовать сервер за пределами РФ — это критически важно для VPN.
- Посуточная оплата 20 ₽ — можно тестировать без обязательств.
- Есть опыт развёртывания VPN на этой платформе.
**Альтернатива: IHC.ru (550 ₽/мес, 2 ГБ RAM, 2 ядра).**
- Дешевле, 2 ядра CPU — лучше для торгового бота.
- Но локация только Россия (Москва) — для обхода блокировок может не подойти.
**Бюджетная альтернатива: HOSTORA.RU (200 ₽/мес) или HostVDS (164 ₽/мес).**
- Значительно дешевле, но меньше дискового пространства и нет гарантии качества канала.
- Подходят, если критична экономия.
**Совет:** если нужен зарубежный IP для обхода блокировок, выбирать VDSina.com (Нидерланды) или Hostkey (Европа). Если достаточно российского IP — IHC.ru или HOSTORA.RU.
### 1.4. Совмещение VPN и торгового бота OKX на одном сервере
Торговый бот OKX (например, на Python с библиотекой CCXT или Freqtrade) предъявляет следующие требования:
| Параметр | Минимум | Рекомендуется |
|---|---|---|
| RAM | 512 МБ | 1–2 ГБ |
| CPU | 1 ядро | 2 ядра |
| Диск | 500 МБ–5 ГБ | 20 ГБ |
| ОС | Ubuntu 20.04+ / Debian 11+ | Ubuntu 24.04 |
**Вывод:** 2 ГБ RAM достаточно для одновременной работы VPN-сервера (AmneziaWG + Xray + dnscrypt-proxy ≈ 300–400 МБ) и торгового бота (≈ 500 МБ–1 ГБ). Остаётся запас на ОС и Docker.
**Меры изоляции:**
- Торговый бот запускается в **отдельном Docker-контейнере** с ограничениями по CPU и RAM (`--cpus="0.5" --memory="512m"`).
- VPN-контейнеры изолированы в своей Docker-сети.
- Админ-панель показывает статус **обоих** сервисов.

## 2. Архитектурные решения
### 2.1. Протоколы: что работает в России в 2026 году
Обычный WireGuard и OpenVPN **не работают** — ТСПУ детектирует характерный handshake WireGuard и блокирует соединение в течение секунд. OpenVPN также блокируется.
**Основной протокол: AmneziaWG 3.1.** Модифицированный WireGuard с поведенческой обфускацией. Клиент AmneziaVPN доступен для Windows, macOS, Linux, Android, iOS. На Smart TV и консоли VPN настраивается на уровне роутера (OpenWrt, Keenetic, Asuswrt-Merlin).
**Резервный протокол: Xray VLESS + REALITY.** Модифицированный TLS, заимствующий рукопожатие реального популярного сайта. DPI видит обычный HTTPS-визит и не может отличить прокси-трафик от легитимного.
**Шифрование DNS: dnscrypt-proxy.** Все DNS-запросы VPN-клиентов принудительно перенаправляются через iptables DNAT на внутренний резолвер.
### 2.2. Стек
| Компонент | Роль |
|---|---|
| **AmneziaWG 3.1** | Основной туннель |
| **Xray VLESS + REALITY** | Резервный туннель |
| **dnscrypt-proxy** | Защита DNS |
| **Docker** | Изоляция всех сервисов |
| **FastAPI + SvelteKit** | Админ-панель (WebSocket) |
| **nftables + tc/ifb** | Лимиты гостей |

## 3. Функциональные требования
### 3.1. Пользователи и роли
| Роль | Количество | Права |
|---|---|---|
| **Владелец (Админ)** | 1 | Полный доступ к панели, без лимитов, создание/удаление гостей, просмотр всей статистики, управление ботом |
| **Гость** | До 5 | Только подключение. Нет доступа к панели. Управляется лимитами |
### 3.2. Веб-панель администратора
**Аутентификация:**
- Argon2id hash пароля, минимум 16 символов.
- JWT с refresh token rotation, автоматический выход через 30 минут.
- Rate limiting: 5 попыток в минуту, бан через Fail2ban на 24 часа.
- Опционально: TOTP (2FA).
- Панель доступна по случайному URL (например, `/panel-a7f3b2/`).
**Дашборд:**
| Виджет | Данные |
|---|---|
| **Онлайн-устройства** | Имя, IP в туннеле, протокол, текущая скорость ↓/↑, время подключения |
| **Real-time графики** | Скорость по каждому устройству, обновление каждые 2 секунды через WebSocket |
| **Суммарный трафик** | ↓/↑ за день, неделю, месяц, всё время |
| **Нагрузка сервера** | CPU, RAM, диск, сетевая нагрузка |
| **Статус сервисов** | AmneziaWG, Xray, dnscrypt-proxy, Docker, **торговый бот** — индикаторы |
| **Статус торгового бота** | Онлайн/офлайн, PnL за день, количество сделок, текущие позиции |
| **Геолокация** | Карта с точками подключения (GeoIP) |
**Управление устройствами:**
| Действие | Описание |
|---|---|
| **Создать устройство** | Ввод имени → генерация ключей → `.conf` + QR-код |
| **Просмотр** | IP, публичный ключ, трафик, последняя активность, скорость |
| **Отключить** | Мгновенный разрыв через `awg set` |
| **Удалить** | Полное удаление ключей и конфига |
| **Экспорт** | Скачивание `.conf`, QR-код |
**Управление гостевыми аккаунтами (до 5):**
| Параметр | Реализация |
|---|---|
| **Лимит трафика** | Дневной/недельный/месячный/общий. Счёт через `nftables` counter |
| **Ограничение скорости** | ↓ и ↑ в Мбит/с через `tc` + `ifb` (класс `hfsc`) |
| **Временное окно** | Cron-задача каждые 5 минут |
| **Срок действия** | Дата/время, автоматическая деактивация |
| **Приоритет QoS** | Низкий/средний/высокий |
| **Логирование** | Отдельный журнал, экспорт в CSV |
**Управление торговым ботом:**
| Действие | Описание |
|---|---|
| **Старт/Стоп** | Запуск и остановка контейнера бота через Docker API |
| **Статус** | Онлайн/офлайн, uptime, потребление CPU/RAM |
| **Логи** | Просмотр последних 100 строк логов бота |
| **PnL** | Прибыль/убыток за день, неделю, месяц (если бот предоставляет API) |
| **Сделки** | Количество сделок за период |
| **Настройки** | Просмотр и редактирование `.env` файла бота (API-ключи OKX, стратегия) |
**Настройки VPN:**
- Параметры обфускации AmneziaWG (Jc, Jmin, Jmax, S1–S4, H1–H4).
- Переключение AmneziaWG / WireGuard.
- Включение/отключение Xray Reality.
- Выбор домена маскировки для Reality (SNI).
- Резервное копирование и восстановление (ZIP).

## 4. Требования к безопасности
### 4.1. Защита сервера
| Мера | Реализация |
|---|---|
| **SSH** | Только по ключам, non-root, нестандартный порт (22000–65000), Fail2ban |
| **Firewall** | UFW: default deny incoming. Только SSH, VPN-порт (UDP), 443/tcp, порт панели |
| **Fail2ban** | Защита SSH и панели, бан через UFW |
| **Автообновления** | `unattended-upgrades` |
| **Sysctl** | `ip_forward=1`, отключение ICMP redirect, SYN cookies, BBR |
| **Изоляция** | Docker с capabilities `NET_ADMIN`, `SYS_MODULE` |
| **Аудит** | Логирование всех действий администратора |
### 4.2. Защита VPN-трафика
| Мера | Реализация |
|---|---|
| **Криптография** | AmneziaWG: ChaCha20-Poly1305, Curve25519, BLAKE2s |
| **Обфускация AmneziaWG** | Jc=4–12, Jmin=40, Jmax=70, S1=10, S2=10, H1–H4 |
| **Маскировка Xray Reality** | Домен: не `google.com` / `microsoft.com`. Выбирать локальный ресурс (банк, финтех, e-commerce) |
| **DNS-защита** | dnscrypt-proxy + iptables DNAT |
| **PSK** | Уникальный Pre-Shared Key для каждого пира |
### 4.3. Защита веб-панели
| Мера | Реализация |
|---|---|
| **HTTPS** | Caddy с Let's Encrypt |
| **CSRF-защита** | Токены для всех изменяющих запросов |
| **CSP** | Строгая Content-Security-Policy |
| **Скрытие панели** | Случайный URL, IP whitelist (опционально) |
### 4.4. Изоляция торгового бота
| Мера | Реализация |
|---|---|
| **Отдельный контейнер** | Бот в своём Docker-контейнере, не имеет доступа к VPN-контейнерам |
| **Ограничения ресурсов** | `--cpus="0.5" --memory="512m"` — бот не может «съесть» ресурсы VPN |
| **API-ключи OKX** | Хранятся в `.env` файле с правами `600`, не передаются в логи |
| **Сетевая изоляция** | Бот не имеет доступа к внутренней Docker-сети VPN |

## 5. План работы ИИ-агента (пошагово)
### Этап 1: Исследование и подготовка (1–2 дня)
1. **Проведи обзор** актуальных версий AmneziaWG, Xray-core, dnscrypt-proxy.

4. **Определи** минимальные системные требования: RAM 2 ГБ, диск 20 ГБ, CPU 1 vCPU.
5. **Создай** структуру репозитория согласно разделу 2.3.
### Этап 2: Скрипт установки (2–3 дня)
1. Напиши `install.sh` с интерактивным меню:
   - Проверка root-прав, ОС, ресурсов (RAM, диск).
   - Установка Docker, UFW, Fail2ban, nftables.
   - Генерация ключей AmneziaWG (Curve25519) и Reality (X25519).
   - Случайный выбор порта AmneziaWG (20000–60000/UDP).
   - Настройка UFW, sysctl, BBR.
   - Запуск Docker Compose (включая контейнер торгового бота).
2. Напиши `setup.sh`:
   - Ввод пароля администратора (минимум 16 символов).
   - Опционально: домен для Let's Encrypt.
   - Выбор домена маскировки для Reality.
   - **Ввод API-ключей OKX для торгового бота** (опционально, можно позже).
   - Вывод итоговой информации: IP, порты, URL панели, логин, QR-код для админа.
### Этап 3: VPN-ядро (3–4 дня)
1. **AmneziaWG-контейнер:** сборка из исходников, случайные параметры обфускации, клиентские IP в `10.8.0.0/24` с PSK.
2. **Xray-контейнер:** сборка Xray-core, VLESS + REALITY на 443, маскировка под выбранный домен.
3. **dnscrypt-proxy-контейнер:** внутренний резолвер на `172.20.0.2:53`.
4. **Docker Compose:** изолированная сеть `172.20.0.0/24`, capabilities, volumes, healthchecks, автоматический restart.
5. **Контейнер торгового бота:** отдельная сеть, ограничения ресурсов.
### Этап 4: Бэкенд панели (5–7 дней)
1. **FastAPI-приложение:**
   - Модели SQLAlchemy: `User`, `Device`, `Guest`, `TrafficLog`, `AuditLog`, `BotConfig`, `BotLog`.
   - JWT + refresh token rotation, Argon2id.
   - API endpoints для VPN, гостей, бота.
2. **WebSocket-сервер:** каждые 2 секунды — скорость, трафик, статус.
3. **Интеграция с AmneziaWG:** `awg show`, `awg set`.
4. **Интеграция с traffic control:** скрипт `tc_manager.py` для `tc` + `ifb`.
5. **Управление лимитами через nftables:** counter-ы, cron-проверка.
6. **Интеграция с Docker API** для управления торговым ботом (старт/стоп/логи).
### Этап 5: Фронтенд панели (5–7 дней)
1. **SvelteKit-приложение:** вход, дашборд, устройства, гости, настройки, аудит, **бот** (статус, логи, PnL).
2. **WebSocket-клиент** для real-time.
3. **Адаптивный дизайн** (mobile-friendly), тёмная тема.
### Этап 6: Безопасность и тестирование (3–5 дней)
1. Настройка UFW, Fail2ban, SSH hardening.
2. Настройка Caddy для HTTPS + Basic Auth.
3. **Тесты:**
   - Unit-тесты для API.
   - Интеграционные тесты для VPN-подключений.
   - Проверка утечек DNS (`dnsleaktest.com`) и IP (`ipleak.net`).
   - Проверка устойчивости к DPI (тест с ТСПУ-симулятором).
   - Проверка rate limiting и CSRF.
   - **Тест одновременной работы VPN и торгового бота** — убедиться, что бот не влияет на скорость VPN.
### Этап 7: Документация и релиз (2–3 дня)
1. `README.md` — инструкция по установке, включая **рекомендации по выбору VPS с оплатой картой МИР** и **настройке торгового бота OKX**.

## 6. Технические детали реализации
### 6.1. Ограничение скорости через tc + ifb
```bash
# Загрузка модулей
modprobe ifb
modprobe act_mirred
# Создание ifb-интерфейса
ip link add ifb0 type ifb
ip link set ifb0 up
# Перенаправление входящего трафика на ifb
tc qdisc add dev awg0 handle ffff: ingress
tc filter add dev awg0 parent ffff: protocol ip u32 \
    match u32 0 0 action mirred egress redirect dev ifb0
# Шейпинг на ifb0
tc qdisc add dev ifb0 root handle 1: hfsc default 10
tc class add dev ifb0 parent 1: classid 1:1 hfsc sc rate 1000mbit ul rate 1000mbit
tc class add dev ifb0 parent 1:1 classid 1:10 hfsc sc rate 10mbit ul rate 10mbit
tc filter add dev ifb0 parent 1: protocol ip prio 1 u32 \
    match ip dst 10.8.0.2/32 flowid 1:10
```
### 6.2. Учёт трафика через nftables
```bash
# Создание counter для каждого гостя
nft add table ip vpn_quota
nft add chain ip vpn_quota forward { type filter hook forward priority 0\; }
nft add rule ip vpn_quota forward ip saddr 10.8.0.2 counter name guest1_traffic
nft add rule ip vpn_quota forward ip daddr 10.8.0.2 counter name guest1_traffic
```
Периодическая проверка (cron каждые 5 минут):
```bash
TRAFFIC=$(nft list counter ip vpn_quota guest1_traffic | grep -oP 'bytes \K\d+')

    awg set awg0 peer <PUBLIC_KEY> remove
fi
```

**Выбор домена:** не использовать `google.com` и `microsoft.com` — цензоры мониторят их. Выбирать популярный локальный ресурс: банк, финтех, e-commerce. Требования: TLS 1.3 + HTTP/2, не заблокирован у клиента.
### 6.4. Параметры обфускации AmneziaWG
| Параметр | Диапазон | Описание |
|---|---|---|
| Jc | 1–128 (реком. 4–12) | Количество junk-пакетов перед handshake |
| Jmin | 40–70 | Минимальный размер junk-пакетов |
| Jmax | 70–100 | Максимальный размер junk-пакетов |
| S1 | 10 | Size prefix для первого пакета |
| S2 | 10 | Size prefix для второго пакета |
| H1–H4 | Случайные | Header ranges |
**Preset для мобильных операторов (Tele2, Yota, Megafon):** Jc=3, узкий Jmax.
