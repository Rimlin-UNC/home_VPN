# 🔐 StealthNode — модель безопасности

## 1. Защита сервера

| Мера | Реализация |
|---|---|
| Фаервол | UFW: `deny incoming`; открыты только SSH, 443/tcp (Vision), случайные TCP-порты gRPC/XHTTP, случайный UDP-порт HY2, порт панели |
| Fail2ban | SSH: бан 24 часа после 3 неудачных попыток |
| SSH | Опциональное усиление: нестандартный порт, вход только по ключам (с предупреждением проверить новое подключение) |
| Автообновления | `unattended-upgrades` |
| sysctl | BBR (`fq`+`bbr`), отключение ICMP-redirect/source-route, SYN-cookies, увеличенные буферы. Форвардинг НЕ включается: стек — прокси, а не маршрутизируемый туннель |
| Изоляция | Все сервисы — контейнеры с минимальными правами (без NET_ADMIN: прокси не требует); бот — в отдельной сети |

## 2. Защита и живучесть VPN-трафика (ТСПУ-2026)

| Мера | Реализация |
|---|---|
| Основа | Xray VLESS + REALITY: заимствование TLS-handshake реального сайта (активные пробы DPI получают подлинный ответ сайта-донора) |
| Мульти-транспорт | TCP/Vision :443 + gRPC + XHTTP — при детекте одного профиля пользователь переключается на другой (именно так выживают сервисы после мая 2026) |
| Случайность | gRPC serviceName, XHTTP path, короткий ID, порты резервов и HY2 — уникальны при каждой установке («сигнатур по умолчанию» нет) |
| Резерв Hysteria2 | QUIC + Salamander (поток без сигнатуры), masquerade-прокси к сайту-донору; сознательно резерв, а не основа: UDP троттлят ~15% и блокируют ~5% провайдеров |
| Версия Xray | Закреплена v26.7.28: с v26.9.8 сервер требует X25519MLKEM768 — старые клиенты перестали бы подключаться |
| Домен маскировки | Запрет google/microsoft (и на уровне панели, и в скриптах); рекомендации — ресурсы «белого списка» РФ |
| DNS | Системный DNS контейнеров xray/hysteria = наш dnscrypt-proxy (172.20.0.10) → пользовательские запросы уходят наружу только шифрованными (DNSCrypt/DoH/PQDNSCrypt) |

## 3. Защита веб-панели

| Мера | Реализация |
|---|---|
| Доступ | Случайный путь `/p-XXXXXXXX/`; всё остальное на порту — 404 |
| Пароль | Argon2id, минимум 16 символов |
| Сессии | JWT access 30 мин (автовыход) + refresh 14 дней с ротацией; повторное использование отозванного refresh ⇒ отзыв всех сессий |
| Брутфорс | 5 попыток/мин (in-memory) + бан IP на 24 часа после 5 неудачных (в БД) |
| HTTPS | Caddy: Let's Encrypt при заданном домене, иначе internal CA |
| Заголовки | CSP `default-src 'self'`, X-Frame-Options DENY, nosniff, no-referrer |
| CSRF | Cookie-сессии не используются (Bearer-токены) — классический CSRF неприменим |
| Статистика Xray | StatsService слушает только localhost контейнера xray; доступ — только через docker exec из backend |

## 4. Изоляция торгового бота

Отдельная сеть `botnet` (нет доступа к stealthnet), лимиты `0.5 CPU / 512M`,
`bot.env` с правами 600, маскировка ключей в API, безопасный режим симуляции
по умолчанию, лимит размера ордера.

## 5. Известные компромиссы (принятые осознанно)

1. **docker.sock в backend** — для управления клиентами Xray (перезапуск),
   чтения статистики и управления ботом. Смягчение: панель за секретным путём,
   JWT, анти-брутфорс, полный аудит.
2. **UFW и Docker** — опубликованные порты Docker идут через NAT в обход UFW.
   Модель не ослабляется: наружу открыты ровно порты сервисов из compose.
3. **Самоподписанный сертификат для HY2** — домен для личного сервера часто
   отсутствует; клиенты подключаются с `insecure=1` + SNI сайта-донора
   (стандартная практика HY2 без домена). Сам сертификат нигде не проходит
   проверку подлинности — но без неё HY2 всё равно шифрован TLS 1.3 поверх QUIC,
   а подлинность канала обеспечивает пароль + Salamander.
4. **Пер-юзерный лимит скорости удалён** — в прокси-стеке трафик клиентов
   неразличим до выхода из Xray; вместо шейпинга: квоты трафика по встроенной
   статистике Xray, временные окна и сроки действия.
5. **HY2 — один аккаунт владельца** — у Hysteria2 нет удобного per-user
   API для квот; гостевые лимиты реализованы на Xray (там есть per-user
   статистика).

## 6. Аудит

Все изменяющие действия администратора (входы, устройства, гости, бот,
настройки, восстановления) фиксируются в журнале аудита с IP — вкладка «Аудит».
