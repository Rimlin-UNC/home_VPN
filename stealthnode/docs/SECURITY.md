# 🔐 StealthNode — модель безопасности

## 1. Защита сервера

| Мера | Реализация |
|---|---|
| Фаервол | UFW: `deny incoming`, открыты только SSH, порт AWG (случайный UDP), 443/tcp (Xray), порт панели (случайный TCP) |
| Fail2ban | SSH: бан 24 часа после 3 неудачных попыток |
| SSH | Опциональное усиление при установке: нестандартный порт, `PasswordAuthentication no`, root только по ключу (с предупреждением о проверке нового подключения) |
| Автообновления | `unattended-upgrades` (обновления безопасности) |
| sysctl | `ip_forward`, BBR (`fq` + `bbr`), отключение ICMP-redirect/source-route, SYN-cookies, увеличенные буферы |
| Изоляция | Все сервисы — в контейнерах; минимальные capabilities (только `NET_ADMIN`/`NET_RAW` у AmneziaWG) |

## 2. Защита VPN-трафика

| Мера | Реализация |
|---|---|
| Криптография | AmneziaWG: Curve25519, ChaCha20-Poly1305, BLAKE2s, SipHash24 |
| Обфускация | Случайные Jc (4–12), Jmin/Jmax, S1–S4, H1–H4 (вне зарезервированных 1–4) — у каждого сервера уникальные «сигнатуры» |
| PSK | Уникальный Pre-Shared Key на каждого пира (постквантовый бонус + защита от перепривязки) |
| Xray REALITY | Заимствование TLS-handshake реального сайта; версия 26.7.28 выбрана сознательно: с v26.9.8 сервер требует постквантовый X25519MLKEM768, что ломает большинство клиентов |
| Домен маскировки | Запрет google/microsoft; валидация на уровне панели и скриптов |
| DNS | Весь plaintext-DNS из туннеля (любой адрес, не только «правильный») перехватывается DNAT на dnscrypt-proxy → уходит шифрованным |

## 3. Защита веб-панели

| Мера | Реализация |
|---|---|
| Доступ | Случайный путь `/p-XXXXXXXX/`; всё остальное на порту отвечает 404 (сервер «пуст» для сканеров) |
| Пароль | Argon2id, минимум 16 символов |
| Сессии | JWT access 30 мин (автовыход по ТЗ) + refresh 14 дней с **ротацией**; повторное использование отозванного refresh ⇒ отзыв всех сессий |
| Брутфорс | 5 попыток/мин (in-memory) + бан IP на 24 часа после 5 неудачных (персистентно, в БД) |
| HTTPS | Caddy: Let's Encrypt при заданном домене (HTTP-01), иначе internal CA (самоподписанный) |
| Заголовки | Строгая CSP (`default-src 'self'`, без внешних CDN), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer` |
| CSRF | Не используются cookie-сессии → классический CSRF неприменим; все изменяющие запросы требуют Bearer-токен |
| Пароль из .env | Используется один раз при первичной инициализации, захеширован в БД; смена пароля отзывает все refresh-токены |

## 4. Изоляция торгового бота

| Мера | Реализация |
|---|---|
| Сеть | Отдельная docker-сеть `botnet` — бот не видит stealthnet (VPN-сервисы) |
| Ресурсы | Жёсткие лимиты `cpus: 0.5, memory: 512M` — не «съест» ресурсы VPN |
| Секреты | `bot.env` с правами 600; в панели ключи замаскированы; в логи не пишутся |
| Исполнение | По умолчанию симуляция; боевой режим требует явного `OKX_DRY_RUN=false`; лимит `OKX_MAX_ORDER_USDT` на один ордер |

## 5. Известные компромиссы (принятые осознанно)

1. **docker.sock в backend.** Нужен для `awg`-команд в контейнере AWG, перезапусков
   и управления ботом. Компромисс: root-доступ к хосту при компрометации бэкенда.
   Смягчение: панель за секретным путём, JWT, брутфорс-защита, аудит всех действий.
2. **UFW и Docker.** Опубликованные порты Docker идут через NAT в обход UFW.
   Это не ослабляет модель: наружу открыты ровно порты сервисов из compose.
3. **Приватные ключи клиентов в БД.** Нужны для перевыдачи конфигов/QR из панели.
   БД живёт на диске сервера с правами root-only; в бэкап попадает — храните бэкап
   как секрет.
4. **Самоподписанный сертификат без домена.** Браузер предупредит один раз;
   трафик всё равно шифрован. Для строгости — укажите домен при установке.
5. **tc на userspace-интерфейсе.** На экзотических ядрах qdisc для TUN может
   не примениться — код логирует ошибку; лимиты download гарантированы на большинстве
   ядер, fallback описан в TROUBLESHOOTING.md.

## 6. Аудит

Все изменяющие действия администратора (входы, создание/удаление устройств и гостей,
управление ботом, смена настроек, восстановления) пишутся в журнал аудита
(вкладка «Аудит») с фиксацией IP.
