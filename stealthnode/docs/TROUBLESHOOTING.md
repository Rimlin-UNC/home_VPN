# 🔧 StealthNode — устранение неполадок

## ВНИМАНИЕ: симптомы не блокировки сервером, а детекта ТСПУ

Со временем ТСПУ вашего региона может научиться тормозить конкретный профиль.
Признаки: **основной TCP-профиль стал медленным/рвётся, но резервы работают**.
Это не поломка: переключайте телефоны на gRPC/XHTTP (ссылки уже у каждого
устройства). Если деградируют все Xray-профили — у владельца в «Настройках»
есть Hysteria2. Совет дня (2026): держите у клиентов минимум два транспорта
и чаще меняйте домен маскировки (`sudo ./setup.sh` → пункт 2).

## Быстрая диагностика

```bash
cd /opt/stealthnode
docker compose ps                    # все контейнеры Up?
docker compose logs --tail=50 xray
docker compose logs --tail=50 hysteria
docker compose logs --tail=50 backend
```

## Панель не открывается

| Причина | Что делать |
|---|---|
| Забыли адрес | `cat /root/stealthnode-credentials.txt \| grep "Веб-панель"` — там полный URL с секретным путём |
| Контейнер упал | `docker compose up -d`, смотрите `docker compose logs caddy backend` |
| «Bad Gateway» от Caddy | backend не отвечает: `docker compose logs backend` |
| Предупреждение о сертификате | Без домена это нормально (self-signed): примите исключение. Для «зелёного замка» задайте домен переустановкой и сменой `PANEL_DOMAIN` в `.env` |

## «502»/пустые графики, а VPN работает

Статистика Xray берётся через `docker exec xray xray api statsquery` —
проверьте, что контейнер xray называется `stealthnode-xray`
(`docker ps`) и backend видит `/var/run/docker.sock` (он смонтирован в compose).

## VPN не подключается ни одним профилем

1. **Провайдер полностью режет UDP** на вашей линии — HY2 умрёт первым,
   но TCP-профили должны жить; если умерли все три — см. следующий пункт.
2. **Домен маскировки поменял TLS-поведение** (донор должен отвечать
   TLS 1.3 + HTTP/2): `sudo ./setup.sh` → 2 → введите другой домен
   (например `ozon.ru`). Скрипт перезапустит xray и hysteria —
   ссылки обновятся в панели автоматически.
3. **Блокировка порта**: все «лишние» порты случайны при установке —
   проверьте статус в UFW: `sudo ufw status` (должны быть SSH, 443,
   два TCP-резерва, UDP HY2 и порт панели).
4. **Клиент слишком старый/новый**: стек закреплён на Xray 26.7.28 —
   старые клиенты (до 1.8) без Vision могут не подключиться к TCP-профилю;
   скажите пользователю обновить приложение либо использовать gRPC/XHTTP ссылку.

## Трафик не учитывается / лимиты не срабатывают

- Квоты проверяются раз в 5 минут — лёгкий перерасход («догнать» за рывком)
  допустим и не является багом.
- Счётчики считаются с момента появления снапшота (coupe-контроль раз в минуту);
  сразу после установки суммы окна могут быть меньше фактических.
- У пользователя не идёт трафик мимо Xray: счёт идёт по статистике Xray, а не
  по интерфейсу гипервизора VPS.

## Бот не торгует / ошибки OKX

Смотрите `docker compose logs trading-bot`. Частые причины: кредит льготного
баланса демо (проверьте `OKX_DRY_RUN`), не хватает прав у ключа (нужен Trade,
НЕ Withdraw), IP-ключ не совпадает с IP VPS (в OKX привязка по белому списку).

## Откат после обновления Xray/Hysteria

Версии закреплены в compose. Если при умышленном обновлении клиенты отпали
(привет, ML-KEM в 26.9.8): верните тег в `docker-compose.yml` и
`docker compose up -d`.

## Бэкап / восстановление

- Вкладка «Настройки» → «Скачать бэкап»: ZIP с `config.json` Xray, базой
  панели (устройства/гости/снапшоты) и ботом.
- Восстановление ZIP **перезаписывает** конфиг Xray и перезапускает контейнер;
  для полной идентичности после restore-холодного старта перенесите `.env`
  (там пароли HY2, порты, секреты панели и пути).

## Если совсем ничего

```bash
cd /opt/stealthnode && docker compose down
docker compose up -d --build
```

Ничего из `.env`/config.json при этом не теряется.
