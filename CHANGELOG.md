## [2.1.0] — 2026-10-14

Связка «российский мост → зарубежный выход» — по обращению «из России к серверу никак не
попасть, нужна связка». Пошагово: [docs/RELAY.md](docs/RELAY.md).

### Добавлено
- **Выход** (зарубежный сервер): `stealthnode exit enable <IP моста>` / `install.sh --exit-for IP`.
  Отдельный инбаунд `sn-bridge-in` (VLESS + XHTTP stream-one + REALITY) на случайном порту
  40000–49999, открытый в UFW только для IP моста, учётная запись `sn-bridge` без лимитов (к
  профилям пользователей не привязана, в подписки не попадает), мост — в исключениях fail2ban.
  Команда печатает ссылку выхода, делает архив и выдаёт готовую команду для моста;
  `exit link|status|disable`.
- **Мост** (российский сервер): `install.sh --restore <архив выхода> --exit-link 'vless://…'` /
  `stealthnode bridge set|status|off`. Исходящий `sn-exit` первым (по умолчанию). Российские сайты
  (.ru/.su/.рф, ВК, Яндекс, Сбер, geoip:ru) идут напрямую с моста (`--no-ru-direct` — тоже через
  выход). DNS для прямого трафика — системный резолвер моста, домены зарубежных сайтов
  разрешает выход. Telegram-бот и запросы панели идут через выход (`panelOutbound`). Перед
  включением мост проверяет, что выход доступен и REALITY на нём отвечает, иначе ничего не меняет.
- Перенос на мост архивом выхода: тот же домен, ключи, пользователи и подписки. Родственникам
  ничего делать не нужно. Роль выхода из архива на мосту снимается автоматически.
- `stealthnode doctor`: раздел «Связка» (инбаунд и UFW на выходе; доступность и маскировка
  выхода, исходящий по умолчанию, panelOutbound на мосту). С `--e2e` показывается внешний IP через
  туннель: должен быть IP выхода, а российские сайты — с IP моста. A-запись на мост на выходе
  считается нормой.
- `install.sh --proxy socks5h://…` — загрузки по HTTPS (GitHub, Caddy) через прокси, если с
  российской площадки они недоступны (например, SSH-туннель к выходу). Внешний IP определяется
  напрямую.
- `stealthnode restore --no-env` (файлы и БД без `.env`).
- Документация: `docs/RELAY.md` (схема, шаги для 95.182.99.147 → 31.59.126.178, проверка,
  неполадки, приватность), README, INSTALL, OPERATIONS, ARCHITECTURE, SECURITY, TESTING,
  TZ-REVIEW п. 2.9.
- Тесты: 15 unit (ссылка выхода, шаблон обеих ролей, provision против фейковой 3x-ui, CLI с
  фейковыми ufw/fail2ban, проверка выхода по TLS); **E2E на настоящем Xray 26.10.10**: клиент →
  мост → выход, все три профиля выходят с выхода, `.ru` — с моста, без выхода российские сайты
  работают; bats — проверка новых флагов и атомарной замены каталога; CI на настоящей 3x-ui — обе роли через петлю 127.0.0.1,
  счётчик трафика моста растёт.

### Исправлено
- `install.sh --restore`: после слияния `.env` из архива с параметрами нового сервера второй шаг
  восстановления затирал его архивной версией. Терялись IP нового сервера и (для моста) ссылка
  выхода. Теперь БД и профили восстанавливаются без `.env` (`restore --no-env`).
- `doctor`: недоступный dnscrypt-proxy на мосту — предупреждение, а не ошибка (там DNS нужен
  только для российских сайтов, и сначала спрашивается системный резолвер).
- Гонка при повторном запуске `install.sh` (поймал CI): CLI, запущенный таймером (certsync
  стартует через 5–15 минут после загрузки), писал байткод в каталог приложения во время его
  замены, и установка падала с `rm: Directory not empty`. Теперь каталог заменяется атомарно
  (версия рядом и символьная ссылка, `replace_dir`), таймеры на время обновления
  останавливаются, а CLI не пишет `__pycache__` (`PYTHONDONTWRITEBYTECODE`). Регрессионные
  bats-тесты: 25 замен подряд, пока фоновый процесс пишет в каталог.

## [2.0.1] — 2026-10-14

Исправление по обращению «после смены пароля не могу зайти». Разбор причин — по исходникам
3X-UI v3.10.0 (`login_limiter.go`, `index.go`, `user.go`, `main.go`) и [TZ-REVIEW, п. 4.8](docs/TZ-REVIEW.md).

### Исправлено
- **Повторный запуск `install.sh` сбрасывал пароль панели**, изменённый в веб-интерфейсе, на
  исходный из `.env` (`configure_xui` при каждом запуске вызывал `x-ui setting -username -password`).
  Повторный запуск нужен, например, для `--ssh-close-22`, обновления или `--tg-token` — после него
  новый пароль «переставал подходить». Теперь логин/пароль задаются только чистой панели или
  стандартным admin/admin; совпадение с `.env` проверяется по bcrypt-хешу в БД панели (системная
  libcrypt), без попытки входа — лимит 3x-ui, fail2ban и уведомления Telegram-бота не задеваются.
  При любой неясности (сбой проверки) пароль не трогается.
- `/root/stealthnode-credentials.txt`, `stealthnode info --secrets` показывали устаревший пароль
  из `.env`. Теперь — «изменён в веб-интерфейсе панели» (и действующий логин из БД), для
  admin/admin — предупреждение.
- fail2ban считал отказы встроенного лимита 3x-ui (`reason="too many failed attempts"`): после
  5 ошибок 3x-ui 15 минут отвергает и **верный** пароль, и каждая такая попытка шла в зачёт бана
  на 24 ч — владелец, вспоминающий новый пароль, гарантированно оказывался заблокирован. Такие
  строки больше не считаются (`ignoreregex`, привязан к концу строки — подделать через логин
  нельзя); jail панели смягчён: 10 настоящих ошибок за час → бан на 1 ч (было 5 за 10 мин → 24 ч),
  упорных по-прежнему ловит recidive (неделя).
- `--admin-ip` не запоминался: повторный запуск без флага убирал IP из исключений fail2ban.
  Теперь хранится в `.env` (`SN_ADMIN_IP`), можно несколько через запятую, проверяется формат.
- `stealthnode env set SN_XUI_PASSWORD=…` молча менял только `.env` (панель — нет), после чего
  файл учётных данных показывал неверный пароль. Теперь команда отказывает и подсказывает
  `stealthnode panel-password`.
- CI: проверки вида `! cmd` под `set -e` никогда не роняли шаг (особенность bash), т.е. часть
  проверок SSH-шага (закрыт 22, удалено правило UFW) фактически не работала. Заменены на
  `! cmd || exit 1`.

### Добавлено
- `stealthnode panel-password` — сменить или восстановить логин/пароль панели: спрашивает пароль
  (Enter — случайный) или `--password`/`--random`, `--username`, `--reset-2fa`; применяет через
  штатный `x-ui setting` с проверкой по БД, сохраняет в `.env` и файл учётных данных, перезапускает
  панель (сбрасывает 15-минутную блокировку входа 3x-ui) и снимает баны fail2ban, мешающие войти
  в панель (jail панели и recidive для тех же IP). `--check` — действует ли пароль из `.env`.
- `stealthnode unban [IP…|--all]` — список банов по jail (sshd, панель, recidive, 3x-ipl) и снятие.
- `stealthnode doctor`: проверка «вход в панель» (FAIL для admin/admin), число забаненных IP в jail.
- Пароль панели: свой — от 8 символов (было: в `.env` требовалось ≥ 16, и короткий пароль
  ломал повторную установку), предупреждение при длине < 12; максимум 72 байта (bcrypt).
- Документация: OPERATIONS «Вход в панель: смена пароля, „не пускает“, забытый пароль» (таблица
  симптомов и решений, SSH через консоль хостинга), INSTALL, SECURITY, TESTING, ARCHITECTURE.
- Тесты: 14 unit (bcrypt по вектору Go x/crypto, состояния, смена через фейковый `x-ui`, снятие
  банов только для панели), 4 bats (`apply_panel_credentials`), CI на настоящей 3x-ui: вход как
  в браузере (HTTPS через Caddy, CSRF, cookie) → смена пароля через веб-интерфейс → повторная
  установка → пароль сохранён; лимит 3x-ui и бан fail2ban с отдельного IP → восстановление
  `stealthnode panel-password`; `--admin-ip` переживает повторный запуск.

## [2.0.0] — 2026-10-14

Полная переработка по ТЗ v2 ([docs/TZ-v2.md](docs/TZ-v2.md)); разбор ТЗ и принятые решения —
[docs/TZ-REVIEW.md](docs/TZ-REVIEW.md).

### Добавлено
- Установщик `stealthnode/install.sh` для чистой Ubuntu 24.04: предпроверки (ОС, ресурсы, порты,
  внешний IP, A-запись домена, IPv6), журнал `/var/log/stealthnode/install-*.log`, перехват ошибок
  с указанием шага и строки, безопасный повторный запуск.
- Протоколы (Xray 26.10.10 в составе 3X-UI v3.10.0):
  - VLESS + XHTTP (`mode=stream-one`) + REALITY на 443/tcp, без flow, `fp=firefox`;
  - VLESS + TCP + REALITY + Vision на 8443/tcp для iOS (те же ключи и shortId);
  - Hysteria2 + Salamander на 443/udp внутри Xray (общие лимиты и подписка).
- Панель 3X-UI (закреплённая версия, проверка SHA256 установщика): только на 127.0.0.1,
  наружу — через Caddy по HTTPS на отдельном порту; случайные порт, путь, логин и пароль; API-токен.
- Пользователи: одна запись на человека для всех трёх протоколов — общая квота трафика
  (например, 50 ГБ/мес с ежемесячным сбросом), лимит одновременных IP, одна подписка.
- CLI `stealthnode`: `doctor [--e2e] [--speed]`, `user add|del|list|show|limit|reset`, `links`,
  `backup`/`restore`, `cert-sync`, `sni-check`/`sni-set`, `export-config`, `info`, `token-rotate`.
- `stealthnode doctor --e2e`: проверки раздела 8 ТЗ в исправленном виде и реальное подключение
  по каждому профилю клиентом Xray с самого сервера (+ замер скорости).
- Сертификат Hysteria2: Let's Encrypt от Caddy (автосинхронизация по таймеру), до его получения —
  self-signed + `pinSHA256` (без `insecure=1`).
- dnscrypt-proxy (127.0.2.1) как DNS для Xray, резерв — DoH 1.1.1.1.
- Защита: UFW (только нужные порты), fail2ban (SSH 3/10 мин → 24 ч; перебор пароля панели;
  recidive; лимит IP 3x-ui), BBR и sysctl, swap на малых VPS, автообновления безопасности,
  опционально SSH только по ключам и нестандартный порт с безопасным переходом.
- Ежедневные резервные копии (14 шт.) и перенос на новый VPS (`--restore`) без смены ссылок.
- Встроенный Telegram-бот 3x-ui на русском (`--tg-token`, `--tg-chat`).
- Документация: установка, клиенты, обслуживание, безопасность, тестирование, архитектура.
- Тесты: pytest (вкл. векторы RFC 7748 для X25519 и провижининг против фейкового API 3x-ui),
  bats, локальный E2E протоколов на настоящих Xray 26.10.10 и Hysteria 2.13,
  CI GitHub Actions с полной установкой на Ubuntu 24.04 и проверкой контракта с 3x-ui.

### Исправлено до выпуска (найдено тестами и CI на чистой Ubuntu 24.04)
- 3x-ui v3 отдаёт шаблон Xray (`POST /panel/api/xray/`) JSON-строкой внутри `obj` — разбор исправлен.
- `caddy validate` от root создавал `/var/log/caddy/caddy.log` с владельцем root, и служба Caddy
  не запускалась (`permission denied`) — проверка выполняется от пользователя `caddy`.
- dnscrypt-proxy из Ubuntu 24.04 (2.0.45) не понимал ключи новых версий — конфиг совместим с 2.0.x,
  проверяется `dnscrypt-proxy -check`, при отказе остаётся конфиг пакета.
- `sshd -t`/`sshd -T` падали без `/run/sshd` (в Ubuntu 24.04 с `ssh.socket` каталог появляется
  только после первого запуска sshd) — каталог создаётся перед проверкой.
- Смена порта SSH в Ubuntu 24.04: drop-in `ListenStream=ПОРТ` при `BindIPv6Only=ipv6-only` от генератора
  оставлял SSH только на IPv6 (потеря доступа на IPv4-сервере). Теперь порты применяет штатный генератор,
  каждый порт проверяется IPv4-подключением, при неудаче изменения автоматически откатываются.
- Гонка после восстановления из бэкапа: проверка процесса Xray выполнялась раньше, чем 3x-ui
  его перезапускала — `restore` ждёт панель и ядро.
- Добавление/удаление пользователя и повторная установка больше не перезапускают ядро Xray
  (не рвут соединения): 3x-ui применяет изменения клиентов на лету.
- Официальный клиент Hysteria2 требует доверенный CA даже с `pinSHA256` — учтено в документации,
  основной режим — сертификат Let's Encrypt.

### Изменено
- Вместо собственной панели (FastAPI) — 3X-UI v3; вместо Docker — системные службы.
- Торговый бот OKX больше не ставится на VPN-сервер.

### Удалено
- Реализация v1 перенесена в [`legacy/v1/`](legacy/README.md) (история сохранена).

### Безопасность
- Сырые порты панели и подписки не открываются наружу; секреты — в файлах с правами 600.
- Отпечаток `firefox`: единственный, проходящий и фильтр ТСПУ (июнь 2026), и требование
  X25519MLKEM768 в REALITY Xray ≥ 26.9.8 (проверено тестом: `fp=ios` отвергается).
